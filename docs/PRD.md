# PRD — DigiBoard 电子副屏

## 产品目标

- 把单一功能的 LED 数显模拟器升级为**通用电子副屏**：用户指定点阵尺寸（如 80×60），在同一画布上自由组合像素画、LED 数码管与实时信息流，可导出为图片（PNG）或场景文件（YAML），并能在独立全屏播放页常驻展示。

## 用户与使用场景

- 目标用户：想在桌面/副屏上展示个性化 LED 风格内容的开发者与爱好者；使用 Claude Code 的用户（把会话状态挂在副屏上盯进度）。
- 典型场景：
  1. 编辑一个 80×60 点阵：像素画打底 + 大号数码管显示数字/文字 + Claude 会话状态小组件；
  2. 导出 PNG 发到群里，或导出 YAML 传给同事/存档（对方用「新建 → 从 YAML 载入」还原）；
  3. 打开播放页 `/play?scene=<base64-yml>`，全屏当电子副屏常驻；
  4. 本机跑 `pnpm bridge`，小组件实时显示各 Claude Code 会话 busy/idle/waiting、模型、token 用量、当前工具。

## 核心问题

- LED 数显内容被像素网格锁死：数码管本该是「突破像素」的矢量元素（斜切、发光、亚像素定位、可超出画布），而不是逐格点亮的点阵；同时它要像实体面板一样占住一块矩形，而不是浮在像素点上面。
- 内容形态单一：只有数码管，没有像素画与信息流；无法组合、无法导出、无法分享。
- 静态部署拿不到本机数据：浏览器沙箱读不到 `~/.claude`，需要一条安全的本地桥接通路。

## 功能及其意义

| 功能                            | 解决什么               | 为什么需要                                                                                  |
| ------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------- |
| 自定义点阵尺寸（1–200）         | 画布规格固定           | 副屏物理规格各异，尺寸必须用户定义；resize 保留重叠区内容                                   |
| 像素画层（单层多色混搭）        | 无法画点阵图案         | 副屏的基础表达；圆角点阵玩具板（留缝、灭点/亮点），画笔颜色在顶部工具栏，像素值即调色板索引 |
| LED 数码管矢量层                | 数码管被网格锁死       | 核心卖点：斜切/发光/亚像素定位/超出画布，并以矩形整块占据点阵空间，导出时栅格化合成         |
| 信息流小组件（Claude 会话状态） | 内容不「活」           | 副屏的价值在实时信息；注册表机制为后续小组件留扩展点                                        |
| 本地 SSE 桥接（bridge）         | 浏览器读不到本机文件   | 只读 `~/.claude/sessions` + jsonl 尾部，127.0.0.1 only，无 bridge 自动降级演示数据          |
| 导出 PNG                        | 成果无法带走           | 三层按 z-order 合成到离屏 canvas，真实栅格化（含发光滤镜）                                  |
| 保存对话框（YAML / PNG）        | 导出入口分散           | 工具栏「保存」/⌘S 弹窗二选一：YAML 可再导入，PNG 为成品图                                   |
| 拼豆图纸导出                    | 图纸无法直接照着拼     | 对角整格 + 每格灰线 + 5/10 格红线，外扩绘制行列序号与拼豆色号图例                           |
| 导出/导入 YAML                  | 场景无法分享与还原     | 像素 RLE 紧凑编码，round-trip 无损；base64 变体直接进播放页 URL                             |
| 独立播放页                      | 编辑界面不适合常驻展示 | 全屏只读、自适应铺满、F 全屏、E 返回编辑器                                                  |
| 撤销/重做 + 图层管理            | 编辑易失误、内容难组织 | 历史栈上限 100；图层增删/复制/显隐/锁定/四级排序                                            |
| 编辑自动保存                    | 误关页面丢工作         | 每步编辑防抖 400ms 写入 localStorage，刷新自动恢复                                          |

## 功能之间的关系

- 编辑器产出场景 →（防抖自动保存到 localStorage）→ YAML/PNG 导出 → 播放页消费 YAML（URL；本地文件经「新建 → 从 YAML 载入」进编辑器）→ 播放页与编辑器共享小组件数据源（bridge SSE 或 mock 降级）。
- 画布底色固定黑色：数码管/小组件占据的矩形区域整块抠除像素点，露出纯黑面板。
- 三类图层共享同一场景坐标系与合成管线（屏幕渲染与 PNG 导出复用同一套几何/矩阵，保证所见即所得）。

## 范围与非目标

- 范围内：上述功能的编辑、导出、播放、桥接与测试覆盖。
- 范围外：
  - 多用户协作、云端存储、账号体系（场景以文件/URL 传递）；
  - 视频/GIF 导出、动画时间轴；
  - Claude 之外的其它小组件（架构已留注册表扩展点）；
  - 移动端触控专项优化。
